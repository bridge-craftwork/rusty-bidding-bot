# Teaching skills, card fields and modules

Bridge-Classroom tags each lesson with a skill path
(`[SkillPath "bidding_conventions/fourth_suit_forcing"]`), from its
taxonomy (`public/data/skillPaths.json` in ../Bridge-Classroom). Its card
editor and `cardToTaxonomyMapping.js` tie card settings to those skills.
This repository ties the same skills to its card fields and its rules, so
that a lesson, a card setting and the rules that bid it can find each
other:

- **The card field is the convention's canonical ID.**
  `notrump.stayman.play`, not a name of our own: the field is what a card
  says, what the editor writes, and what a module's `card` line reads.
- **A field names its skill**: `skill = "bidding_conventions/stayman"` (or
  a list) in `conventions/card/fields.toml`.
- **A module names the skills it implements**: `skill <path>` header lines
  in its `.bid` file (LANGUAGE.md §3). Basic modules name the course-level
  skills (`basic_bidding/*`, `partnership_bidding/*`) they cover.
- **The known paths** are `conventions/card/skills.toml`: Bridge-Classroom's
  taxonomy (`[taxonomy]`), the bidding tags its lessons use beyond it
  (`[lessons]`), and the paths we propose for conventions it has no skill
  for (`[proposed]`, not in Bridge-Classroom yet). `rbb bid check` warns
  about a path not listed there. The proposals, and the problems found in
  Bridge-Classroom's mapping on the way, are drafted as an issue for it in
  [drafts/bridge-classroom-skill-taxonomy-issue.md](drafts/bridge-classroom-skill-taxonomy-issue.md).

Skills are documentation: they change nothing about how a module loads or
bids.

## The generated map

Generated by `rbb bid skills` from the modules, `fields.toml` and
`skills.toml`; `cargo test` fails when it is out of date. Regenerate with
`cargo run -q -p rbb-cli -- bid skills --doc docs/SKILLS.md`.

Status: **taxonomy**, in skillPaths.json; **lessons only**, a SkillPath
lesson files use that skillPaths.json lacks; **proposed**, ours.
